Leave with

  • Every mint and burn is a log on a public ledger. You can decode it by hand.
  • The pipeline asks a node for logs in small windows, turns blocks into weeks and sums dollars.
  • Silent failures are the real risk. The project caught one that dropped 99.98% of USDC mints.

The pieces

A blockchain is a shared ledger. Ethereum adds a block about every 12 seconds. Each block holds transactions. A transaction that calls a token contract produces a receipt, and the receipt holds logs. A contract emits a log to announce that something happened. We call that announcement an event.

A node answers questions about the ledger through an RPC (remote procedure call). The call eth_getLogs says: give me every log from this contract between block A and block B.

Anatomy of a log

  • address: the contract that emitted it (for example the USDC contract).
  • topics[0]: a fingerprint of the event's name and argument types. It tells you which event this is.
  • other topics: arguments marked indexed, such as the wallet addresses.
  • data: the remaining arguments packed together, such as the amount.

Amounts are whole numbers in the smallest unit. USDC, USDT, PYUSD and BUIDL use 6 decimals, so divide by 1,000,000. Ondo's USD value fields use 18 decimals.

What counts as a mint or a redeem

Every issuer names the events differently. Part of the project's work was a translation table.

From blocks to weeks

A log knows its block number, not its date. The script fetches the real timestamp of a block every 25,000 blocks and interpolates (draws a straight line) between those anchors. The error is under an hour. Weeks start Monday 00:00 UTC. The newest, partial week is dropped.

The traps

1. The silent truncation

A single wide eth_getLogs call over the whole history returned 22 USDC mints out of about 100,000. It did not raise an error. The server just stopped. The fix was to ask in windows of 100,000 blocks and to halve the window whenever a call fails or returns the server's 20,000-result cap. Lesson: a total that looks plausible can still be wrong. Always reconcile against a second source.

2. The wrong decimal place

The first decode of Ondo's dollar value read the wrong data word. Totals were off by a lot, which made the error findable. It was fixed by matching the totals to the dashboard's existing live pipeline (2,416 events on both).

3. Outliers that are errors

The 300 trillion PYUSD mistake would have made PYUSD look larger than the world economy. Two transactions are excluded by hash, and the check script asserts that PYUSD stays plausible.

4. Free RPC limits

One free endpoint blocked the project's IP after about ten calls. Another timed out on USDC's huge history. The script uses a public gateway that tolerates windowed calls. Public infrastructure has rate limits, so design for retries.

How we know it is right

  • Spot checks. Three transactions (a USDC mint of $50,000, a USDT issue of $1 billion, a BUIDL burn of $350,000) were decoded by hand and matched Blockscout's own decoding.
  • Reconciliation. Ethereum mints minus burns land within 16% of DefiLlama's Ethereum supply change for USDC and 5% for PYUSD. The gap is explained by timing and by supply moves that are not mints.
  • Assertions. src/lib/issuance.check.ts fails if the totals or the claims in the summary drift.

Limit

Logs on Ethereum only. A mint on Tron or Solana never appears. Chain coverage comes from supply (DefiLlama), which is a different kind of evidence than logs.

Check yourself

What does topics[0] tell you?

Which event this log is. It is the hash of the event's name and argument types.

A USDC mint's data field is 50,000,000,000. How many dollars?

$50,000. USDC has 6 decimals, so divide by 1,000,000.

Why query 100,000 blocks at a time?

A wide query silently returned a tiny part of the data. Small windows stay under the server's result cap, and the script halves a window that fails.

How do you turn a block number into a week?

Look up the timestamps of anchor blocks every 25,000 blocks, interpolate linearly between them, then bucket by Monday 00:00 UTC.

Name two independent ways the numbers were validated.

Hand-decoded spot checks against an explorer, and reconciliation of mints minus burns against DefiLlama supply changes (also the 2,416-event match with the live Ondo pipeline).
